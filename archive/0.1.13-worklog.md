## Investigation before changing anything
Measured the shipped default field with `node` scripts (not assumed):
- The committed loop the guide locks onto never touched either reflector once settled —
  `reflect()` replayed against the live particle and against `sim.loop` both gave zero hits
  over 200 s. The reflectors only ever affected the very first unguided forecast pass from the
  fixed initial state, before the guide locks a lap; the test asserting "the default forecast
  visibly uses R2" was checking that transient, not the actual steady ride.
- The committed loop also never touched either seeded cooler circle (`circleFraction` dwell was
  exactly 0 for both `C1`/`C2` over a 60 s run with auto-fuel on), so the reactor only ever
  heats and never cools: heat pins at the 120% ceiling and output stays 0 regardless of the
  target. The seeded fuel/cooler circle positions were essentially arbitrary relative to the
  field, not placed on the orbit.

Both are the same root cause: circle and reflector positions were never checked against the
field's actual settled geometry. "Move reflectors to the sides" and "make the target
achievable" turned out to be the same fix — re-seed every fixed-position instrument on the
beam's own settled lap.

## Changes
- **Default speed 30×** (`js/app.js` `DEFAULT_SPEED`, `index.html` slider default/label,
  `README.md`). Reset and page load both start at 30×; the slider still ranges 1–50.
- **Reflectors move with pointer drag.** `js/app.js`: dragging inside a reflector's body now
  sets `drag.mode = 'move'` (previously only magnets could enter that branch; dragging inside a
  reflector did nothing at all). A new `moveReflector()` clamps the reflector anywhere inside
  the chamber interior (not snapped to the frame like magnets — `REFLECTOR_MARGIN = 60`).
  Arrow keys also nudge a selected reflector freely (10 px steps) instead of being disabled for
  reflectors. Rotation (drag outside the shape, wheel, Q/E, the orientation slider) is
  unchanged.
- **Reflectors repositioned to the chamber's left/right flanks** (`js/reactor.js` default
  `reflectors`), found by a search that rejected two failure modes measured along the way:
  (1) assigning `sim.reflectors` after construction without clearing `sim.loop` carries over a
  stale committed loop from the old defaults, so a candidate looks "hit" only because of that
  leftover bias — candidates must be evaluated from a true fresh state (`sim.loop.count = 0`
  before the first `predict()`); (2) counting `reflect()` calls from *any* `integrate()` call
  (including the unguided/guided forecast passes on `this.scratch`) overcounts — only hits on
  `this.particle` during `step()`, or hits replayed against the final settled `sim.loop`, count
  as real interaction. Getting *both* reflectors to graze the same stable lap simultaneously
  was not found after a broad randomized + refined grid search (every joint candidate that hit
  both reflectors individually dropped to hitting only one, or neither, once both were present
  together — the lap-selection process is sensitive to exactly which near-recurrence it locks
  onto, consistent with the churn already documented in the "Prototype boundaries" section).
  Shipped: R2 grazes the settled orbit once every lap (period 7.05 s, locked ~100% of the time
  over a 220 s run); R1 sits on the opposite flank, inert by default, free to drag into a new
  role.
- **Fuel/cooler seed positions re-placed on the new settled orbit**
  (`FUEL_SEEDS`/`COOLER_SEEDS`), each confirmed with `circleFraction` dwell over a 40 s run (all
  five seeds now have nonzero dwell every run, versus zero for both coolers before), clear of
  the magnets, the reflectors, and each other by the same margins `isOpenSpot` enforces for
  player-placed circles, and inside the chamber bounds the `MAX_FUEL`/`MAX_COOLERS` test checks
  (`|x| <= 350 - radius`, `|y| <= 270 - radius`).
- **Output scale and target clarity** (`js/app.js`, `index.html`, `style.css`):
  - `OUTPUT_BAR_MAX` lowered from 30 to 12 (closer to the measured achievable range, see
    below), so the bar isn't mostly empty.
  - A shaded `.target-band` element now marks the *whole* ±`ON_TARGET_BAND` zone, not just a
    marker line — exported `ON_TARGET_BAND` from `js/reactor.js` so the UI reads it instead of
    duplicating the constant.
  - A new "Deviation" row shows a signed percentage of target with colour (cyan = on target,
    blue = low, red = high).
  - The chamber status badge now names the action: "ON TARGET — HOLD HERE", "▲ RAISE OUTPUT
    N%", or "▼ LOWER OUTPUT N%", replacing the flat "ON/OFF TARGET" text.
  - Hint text (index.html, README) updated for drag-to-move reflectors and the new status/band
    semantics.

## Balance measurement (not assumed — measured with `node`, 150 s runs, seed 42)
Default field (3 fuel / 2 cooler, auto-fuel on), sampled after a 30 s settle:

| configuration | median %/s | p10–p90 | max |
|---|---|---|---|
| default | 3.4 | 1.5–5.6 | 6.8 |
| remove a cooler | 1.3 | 0.5–3.1 | 3.8 |
| remove a fuel circle | 2.9 | 1.3–5.4 | 6.8 |
| drag R2 off the orbit | 2.8 | 1.1–5.3 | 6.6 |

The target drifts over [2, 8] %/s (`TARGET_MIN`/`TARGET_MAX`, unchanged). The hands-off default
already lands near the middle of that band and swings across most of it on its own (the orbit's
periodic crossings), and removing a cooler/fuel circle or dragging a reflector off the lap shifts
the achievable range measurably in the expected direction — the player has a lever, not just a
pass/fail check from an unreachable baseline.
