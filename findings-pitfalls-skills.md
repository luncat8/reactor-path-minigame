# Findings and pitfalls

- Keep forecast and live simulation buffers separate. Forecasting must copy the particle into reusable scratch state and must not accumulate live activation or advance the live clock.
- At trajectory crossings, nearest position alone can choose an opposing segment. Prefer segments that continue the heading, and limit guidance acceleration instead of snapping velocity.
- Aiming a guidance vector straight at a look-ahead node pushes an on-track beam forward (thrust, not steering), so every debug vector points along the path. Measuring the correction relative to where the beam would coast fixes thrust but adds a *speed* term that points backwards whenever the beam runs ahead of schedule. Keep only the component lateral to the beam's velocity: steering stays possible, thrust and braking become impossible by construction, and no gate has to be trusted.
- A reference trajectory derived from the live state is already that state's ballistic continuation, so "no force" is an exact fixed point of the whole guidance loop and the guide can never do visible work. Hold a committed reference (a plan from before the current perturbation) and the error terms are real again.
- Track a self-crossing forecast by projection onto segments, seeded on the sample scheduled for the current instant, not by scanning for the nearest node. Node scans snap to samples and can return an opposing pass; a time-seeded window cannot be captured by a crossing and keeps the anchor moving forward.
- Debug arrows must be scaled honestly. A `max(minimum, magnitude·k)` length gives a 0.05 noise force the same 20 px arrow as a real pull, which reads as "the force is wrong" instead of "the force is idle". Use a compressive scale (square root) plus a numeric readout of the actual value.
- Target influence is dwell time, not entry count. Segment-circle overlap multiplied by timestamp differences makes forecasting less sensitive to sample spacing.
- Preserve classic script loading and guarded CommonJS exports so the same core runs under `file://` and Node tests without a build.
- Keep browser tooling external to the runtime tree. The optional Playwright experiment accepts `BROWSER_EXECUTABLE` for environments where automatic browser downloads are unavailable.
