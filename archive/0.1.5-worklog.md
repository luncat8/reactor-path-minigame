2. **Why the 0.1.4 "Route Memory + Forward Aim" does not form a closed loop**:
   - In 0.1.4, `findGuidePoint` was seeded on `seedIndex(route, 0) = round((time - route.t[0]) / dt)`.
   - The search was strictly restricted to a narrow time window $[t - 0.1\text{ s}, t + 0.25\text{ s}]$ around the particle's scheduled clock timestamp on the committed route.
   - **Consequence**: The beam is compared *only* to its own time-parameterized forward extrapolation from 1.8 s ago. When the beam completes a revolution around the chamber (~4 s later) and passes through the same spatial region, it is forbidden from matching the earlier pass ($t = 0\text{ s}$). If unguided physics has a 10–15 px precession between revolutions, the beam follows the drifted path. When route memory expires, a new non-closed extrapolation is committed. The system thus remains an open-loop follower of a sequence of wandering snapshots.

3. **How "Movement Matching" (Phase-Space Attractor) works**:
   - Rather than matching an absolute clock timestamp $t$, Movement Matching operates in state space $(\vec{p}, \vec{v})$.
   - It searches the trajectory for segments that are spatially close ($\le 40\text{ px}$), heading-aligned ($\le 30^\circ$), and separated in trajectory time ($\Delta t \ge 2.0\text{ s}$, representing a different lap).
   - Applying cross-track positional pull and velocity alignment pulls Lap 2 directly onto Lap 1.
   - Because the error decays on each revolution ($|\lambda| < 1$), the trajectory locks into a self-reinforcing, periodic limit cycle (a true closed loop).
