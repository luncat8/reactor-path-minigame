## Development
- `js/reactor.js`:
  - `HEAT_OVERHEAT = 120` ceiling; fuel heating now clamps there instead of at 100, so the reactor can overheat.
  - `fuelSizeFactor(heat)` + `ReactorPlant.fuelRadius(f)`: the fuel cone's live size is full up to a full buffer and shrinks linearly to zero at the ceiling. The shrunk size is the gameplay size — beam dwell (`advance`), click-to-remove (`removeAt`), and rendering all use it — so lifted cones throttle the fuel heat a hot reactor absorbs.
  - `Reactor.maintainFuel()` runs at the end of `step()` while `autoFuel` is checked: clears burned-out circles (fuel ≤ 0) and tops the count up to `autoFuelTarget`, clamped to the fuel maximum. `autoFuel` / `autoFuelTarget` live on the sim (off / initial 3 by default, restored by `reset`), so the policy is deterministic and testable.
- `js/app.js`: auto-fuel checkbox + number input wiring; the last **+ Fuel** press sets the number input (and the sim target), the input edits it live, reset restores both. Fuel circles draw at their live heat-shrunk size and vanish at the ceiling. The heat bar caps at full and turns red past 100% while the number counts up to 120%.
- `index.html` / `style.css`: auto row (checkbox + number input) in the plant card, overheat styling, hint text.
- Decisions taken without user input (adjust if wrong): "depleted" means fully burned out (fuel ≤ 0), not the ≤ 25% click-to-remove threshold; the default auto number is the initial fuel count (3); the cone shrink affects gameplay (dwell / click / draw), not just the drawing — that is what makes it "prevent overheat"; the heat readout now counts past 100% up to 120%.
