# 0.1.3 worklog — 2026-10-05

## Prompt (draft)
Trajectory guidance force "seems to work not as expected" — the debug vectors all point the
same way along the current trajectory line. Requests: find bugs/improvements, set the default
off-time to the next 4 s so the nearest point is not on the same loop, make the force vectors
longer, and draw the current force vector plus the nearest/target point that is pulling the live
particle (debug mode).

## Diagnosis
- Node measurements showed the live guidance force sat within ~2–5° of the velocity: the
  pure-pursuit aim at a look-ahead node (100 ms ahead) reduces to forward thrust when the beam
  already tracks the path, so every vector lay along the trajectory (matches `draft.txt` §5:
  "force should not be same as trajectory direction").
- The forecast self-crosses ~200 times within its horizon; the nearest-node search used distance
  only, so a crossing could capture the beam onto the opposing segment (the pitfall already noted
  in `findings-pitfalls-skills.md`).

## Development
- `js/reactor.js`
  - Raised the forecast guidance dead zone `GUIDANCE_DELAY` 2 s → 4 s (fade stays 1 s).
  - Added `nearestNode`: picks the nearest node whose local tangent agrees with the beam heading,
    falling back to pure distance only when nothing is forward — prevents wrong-loop capture.
  - Rewrote `guidanceVector` to aim at the look-ahead node **relative to the beam's coasting
    position** (`aim − (p + v·lookaheadTime)`). A tracking beam now feels ~no force; deviations
    are corrected cross-track. Heading fade stays measured against the route tangent so a
    well-heading beam still gets a lateral pull. Accepts an optional `debug` sink populated with
    the chosen nearest/target indices and their positions.
  - `integrate` forwards the optional `debug`; `step` captures the live pull into `liveForce` and
    the selection into `liveDebug`.
- `js/app.js`
  - Shared `arrow` helper; forecast vectors lengthened (14–42 px) for visibility.
  - New `drawLiveGuidance`: hollow ring on the nearest node, filled dot on the look-ahead node,
    and a white arrow from the live particle along `liveForce`. Drawn last so it sits on top.
- `index.html` / `style.css`: checkbox label "Show guidance force vectors", legend gains a
  "Current pull" swatch, guidance micro-text and canvas aria updated to the 4 s off-time and the
  live overlay.
- `README.md`, `0.1-plan.md`, `findings-pitfalls-skills.md`: updated to the implemented design.

## Validation

## Limitations and next step
- Duties, cooling, and control ranges remain uncalibrated; no winning preset. The cross-track
  guidance forms a tighter, more self-consistent loop than the old forward-thrust model, so the
  default magnets now settle into a different orbit — re-tune a solvable scenario against it.

**Suggested next step:** with the live-pull overlay, playtest convergence and magnet response,
then run a deterministic sweep over magnet settings to calibrate one verified solvable scenario on
top of the cross-track guidance.
