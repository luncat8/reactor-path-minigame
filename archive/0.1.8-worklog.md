## Review findings (measured, not guessed)
- **The 0.1.7 worklog quoted wrong target deviations.** `experiments/validate-tuned.js` printed
  `100*t.actual/t.desired - 1`, which is `(100·actual/desired) − 1`, not the deviation in percent.
  The real deviations of the default locked loop are **A −100%, B −19%, C −75%**: the stable orbit
  feeds target B and starves A and C. The quoted "A −1%, B +80%, C +24%" was that arithmetic bug
  read as data. Fixed to `(t.actual / t.desired - 1) * 100`.
- **The perturbation scenario in the same script was doubled.** The mutate hook runs before every
  120 Hz step, and its guard `if (t >= 40 && t < 40.02)` passed on two consecutive steps, so the
  "M1 moved 60 px, M2 rotated 0.7 rad" edit actually moved M1 by 120 px and rotated M2 by 1.4 rad.
  With the edit applied once the guidance behaves as documented: one re-commit at the edit, then
  recurrence median 1.0 px and 100% locked in the t55–80 window. The doubled edit is a real
  boundary instead: the field offers no lap the pull can complete and the guide churns through rail
  families without re-locking. Guard replaced with a one-shot flag; the boundary is kept as a
  separate labelled probe so the difference is visible instead of hidden in one aggregate median.
- **Aggregate-only reporting hid both of the above.** `run()` now reports labelled time windows
  (locked pre-edit, transient, recovered) on top of the overall median.
- **"Zombie ride" hypothesis formed and rejected.** The doubled edit's aggregate looked like a stale
  rail frozen forever by the proximity-only ride hysteresis. Gating the freeze on a smoothed ride
  velocity error seemed principled, but the signals overlap once smoothed (healthy p99 ~33 px/s vs
  stale median ~27), and every spurious unseat re-commits a different lap family: the healthy
  default lock collapsed from 4.8 px median / 96% locked to 124.8 px / 9%. Reverted; the freeze
  keeps proximity-only riding, and the finding is recorded.
- Guidance-probe and the tuned numbers were reproduced exactly before any change (recurrence
  median 128.6 px off → 4.8 px on, 96% locked, 98% riding), so the review had a stable baseline.

## Limitations and next step
- No shippable preset yet. The default field locks a stationary orbit that feeds only one target;
  every targeted layout found (five search rounds, ~12k evaluations) breathes with a ±40% duty limit
  cycle that resets the 8-second streak, and that breathing survives both tighter tracking (r5:
  wander 6 px, swing still 47%) and a rolling rail (wander 4 px, swing 82%). The button and preset
  data were therefore not shipped — nothing mislabeled is left in the page.
- The search tool is ready for another pass; the missing term is *stationarity* of the guided lap
  (not the unguided pair's duty, which is dominated by pair-selection noise — measured: default 67%,
  best candidate 20%, random candidate 91%).
- Guide strength 0.9 remains the tuned default for the default scenario; the preset work does not
  change it.

**Suggested next step:** search for stationary lap geometry — score layouts by the long-horizon
spread of the *live* per-target duty (same quantity that breaks the streak) with a longer screen
(≥ 300 s, several limit cycles), seed from the default field's stationary basin as well as the
targeted basins, and only then install a verified winner into a `PRESETS` entry plus a "Load stable
preset" transport button.
