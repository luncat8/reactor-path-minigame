# 0.1.6 worklog — 2026-10-07

## Prompt
Read `archive/0.1.5-report.md` and `archive/0.1.5-worklog.md`; continue development. The 0.1.5
report's suggested next step was to implement Approach A, "Phase-Space Movement Matching":
replace the timestamp-locked guide search with a spatial search across route segments so a later
lap of the beam's own forecast can lock onto an earlier one, instead of being forbidden from ever
seeing it.

## What changed (`js/reactor.js`)
- `findGuidePoint` no longer takes a `seed` (a clock-derived index) and no longer restricts its
  search to a narrow arc-length window around it. It now scans every forward-heading-aligned
  segment of the committed route and keeps the spatially nearest one — the route carries no time
  argument into the search at all. This is the actual mechanism change: before, a beam revisiting
  a region of the chamber on a later lap was mathematically prevented from comparing itself to an
  earlier lap through the same region; now the comparison is unconditional on time.
- Heading alignment (`segment direction · beam direction > 0`) is still what rejects an opposing or
  perpendicular pass of a self-crossing route — this was never about time, so removing the
  time-seeded window does not weaken that guarantee (confirmed by the unchanged
  self-crossing/perpendicular test, and a new test built specifically to exercise cross-lap
  matching).
- Added a small continuity bias: a candidate within `STICKY_RANGE` (3 samples) of the *previous*
  anchor scores `distance² × STICKY_BIAS` (0.6) instead of raw `distance²`, so the projection does
  not flicker between two similarly-close laps frame to frame. A clearly better match elsewhere
  still wins outright, which is what lets a diverging beam actually snap into a different lap.
- Removed `seedIndex`, `GUIDE_BACKTRACK(_TIME)`, `GUIDE_ADVANCE(_TIME)`, `WIDE_MINIMUM`, and the
  `wide` flag on the guide state — all existed only to seed and size the old clock-windowed search
  and have no role once the search is global. `guidanceVector`/`integrate`/`predict`/`step` lost
  the now-unused `seed` parameter that threaded through them.
- Fixed a bug caught by the new test while building it: the continuity bias compared candidate
  index `i` against `previous` even when `previous` was the reset sentinel `-1` (no anchor yet,
  e.g. right after a route commit). Every low-index segment then looked "close to -1" and won a
  bias it hadn't earned, silently preferring the start of the route over a genuinely closer later
  segment. Fixed by requiring `previous >= 0` before applying the bias — recorded in
  `findings-pitfalls-skills.md`.

## Validation
- `node --test tests/*.test.js`: 18/18 pass (17 previous + 1 new). The new test
  (`movement matching locks onto whichever lap of the route is spatially nearest...`) builds a
  synthetic route with two passes near the same point separated by a long, far-away detour and
  checks the beam locks onto whichever is spatially closer, with no time or index hint available to
  the search — this is the behavior the 0.1.4/0.1.5 window made impossible by construction.
- `node experiments/guidance-probe.js`: geometry and 60 s telemetry are essentially unchanged from
  0.1.5 (projection/aim geometry identical; off-route distance, force magnitude, and the
  held-vs-live route memory comparisons all read the same), confirming the rewrite didn't disturb
  normal single-lap tracking.
- `node experiments/movement-matching-probe.js` (new): on the default field, the live beam's
  matched point is tighter than the old clock-seeded sample on 70–83% of steps (avg ~0 px matched
  vs ~0.77 px clock-seeded) even without crossing laps, because projecting onto the true nearest
  point beats snapping to a fixed-index sample. After a magnet-polarity perturbation the gap is
  much larger (avg matched 7.4 px vs clock-seeded 29.7 px over the following 3 s).
- `node experiments/loop-closure-probe.js` (new): measures lap-to-lap drift at a fixed phase
  marker and target-duty stabilization over 60–120 s. Finding: with the current default field
  (`fx = -0.39x`, `fy = -0.64y`, irrational frequency ratio ≈ 1.28, plus four active magnets), an
  unguided orbit's lap-to-lap drift at a fixed phase is large (tens to ~150+ px) — well past the
  40 px default guide reach — so movement matching rarely finds a different lap within reach from a
  cold start with these defaults; closure is real but conditional on two laps already being close.
  This matches the architectural goal (closure is now *possible*, where before it was *forbidden*)
  but not yet a guaranteed default experience. Recorded as a follow-up in `0.1-plan.md`.
- Manual: `node -c js/reactor.js` / `js/app.js` (syntax), and the page served over
  `python3 -m http.server` to confirm `index.html`, `js/reactor.js`, `js/app.js` all load
  (`200` responses); Playwright is not installed in this sandbox so `experiments/browser-smoke.js`
  was not run here — it does not touch anything the guidance rewrite changed (no `seed`/`wide`
  references), so it should be unaffected, but a real run is still worth doing before release.

## Suggested next step
- Retune the base restoring field toward a near-rational `ωx : ωy` ratio (or otherwise reduce
  unguided lap-to-lap drift) so movement matching reliably has something within its 40 px reach to
  lock onto; right now closure only shows up once a magnet layout happens to produce a near-closed
  orbit already. Alternatively, widen the reach (or add a temporary "capture" boost) specifically
  while two laps are converging, then relax it once locked, so first contact doesn't depend on
  starting close.
- Re-run `experiments/loop-closure-probe.js` after any field/magnet retuning to check whether
  late-run lap-to-lap drift actually shrinks relative to early-run drift (the signature of real
  closure) rather than staying flat.
- Run `experiments/browser-smoke.js` once Playwright/a browser is available in the environment
  that will ship this, to catch anything the manual static-serve check can't (pointer drag, wheel,
  keyboard, resize).
